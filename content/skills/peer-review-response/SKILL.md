# peer-review-response — assemble a rebuttal document

Inputs: the reviews themselves, and (if revising a manuscript) the actual
diff/changes made in response.

## 1. Draft unfiltered first (venting draft)

Write a first pass reacting honestly to each review comment, including any
frustration. This draft is never sent — it exists so the annoyance gets
expressed somewhere before the real draft is written, rather than leaking
into the submitted tone.

## 2. Assign blame correctly before drafting content

For every point where a reviewer misunderstood or missed something, reframe
it as the author's fault, not the reviewer's: "there seems to be a
misunderstanding" / "we did not explain this clearly enough," never "the
reviewer is mistaken." Apply this even when the reviewer's misunderstanding
seems clearly avoidable on a careful read — the response should still
apologize and clarify rather than defend the original text.

## 3. Structure the document: overview, then full quote-and-respond

- Open with a short summary of the major changes made in response to the
  most substantive criticisms — this serves an editor who only skims the top.
- Follow with the complete reviews, quoted in full, responses interleaved
  point-by-point immediately after each comment (indent or block-quote the
  original comment for traceability).
- Reply to every point individually, including minor ones — no comment goes
  unaddressed even if the answer is short.
- Lead each point-by-point response with a direct answer (yes/no/agree/
  changed as requested) before elaborating — don't bury the position under
  explanation.
- Where a change was made, quote the actual revised text (with line numbers
  if the venue supports them) so the point can be verified without reopening
  the manuscript.
- Where a reviewer requested an analysis you're skeptical will change
  anything, run it anyway and report the result — refusing outright reads as
  dismissive regardless of the scientific justification.

## 4. Reorder and, if needed, cut for length

- Reorder responses so the most critical issues appear first, regardless of
  the order reviewers raised them — time-pressured readers often only reach
  the top of the document.
- If a hard length limit forces cuts, cut from the bottom (least important)
  upward. Never shorten the treatment of major points to fit everything in.

## 5. Cool off, then write the real draft

Set the venting draft aside. Write the actual submission fresh, applying
steps 2-4, checking specifically for: any residual defensive phrasing,
any comment left unanswered, and any place "simple" was refuted with
abstract assertion instead of a concrete example the reviewer's mental
model missed.

## 6. Final check before sending

- Every review comment has a response (count them against the original).
- No sentence blames the reviewer for confusion.
- The top of the document alone (before the point-by-point) conveys the
  gist of what changed.
- If this is a revision (not a first rebuttal): the manuscript itself was
  actually updated to reflect the feedback — the response document is
  instrumental, not the deliverable.
