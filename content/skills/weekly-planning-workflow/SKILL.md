# weekly-planning-workflow — Clear / Current / Creative across three streams

Inputs: none required. Optional: a specific week to plan for, current stage
of the application cycle if relevant.

## 1. Get Clear — empty the inputs

Capture everything sitting outside a tracked list: unprocessed emails,
loose notes, browser tabs, anything Ethan is still holding in memory rather
than a system. Do this once across all three streams (classes, research,
applications) rather than per-stream — the point is zero untracked
commitments, not a clean list yet.

## 2. Get Current — reconcile each stream against reality

Work each stream in turn:

- **Classes**: mark what's actually done vs. what's still open; flag any
  assignment or exam whose real deadline has drifted from what's tracked.
- **Research**: check "Next Actions" and "Waiting For" against what's
  actually happened — a stalled advisor follow-up or an unanswered request
  belongs here, since it rots silently otherwise.
- **Applications**: check the current calendar month against the fixed
  monthly skeleton in
  [[grad-school-application-timeline-princeton-review]] (May-June research
  + diagnostic GRE, July-August GRE + SOP draft, September school list +
  letter requests, October transcripts + recommender materials, November
  SOP review + subject tests, December submit + confirm). Treat
  recommendation-letter requests and faculty outreach as fixed external
  deadlines with week-scale lead time, not flexible personal tasks that
  slip alongside coursework.

Silently dropped commitments and blurred priorities are the specific
failure mode this step exists to catch — see
[[gtd-weekly-review-asian-efficiency]].

## 3. Get Creative — surface what's ready to activate

Review any "Someday/Maybe" items or parked ideas across the three streams
and decide what's ready to move onto this week's list. This is the only
forward-looking phase; skipping it means the workflow only ever reconciles
the past week and never adds anything new.

## 4. Derive the coming week's priorities

Feed the reconciled, Clear/Current/Creative-passed state from steps 1-3
into the `priority-triage` skill's Eisenhower sort, run per stream. Don't
re-derive priorities from a stale list — use what this pass just surfaced.

## 5. Set the cadence

Budget 60-90 minutes for the first several passes; expect to compress to
30-45 minutes once established. Any fixed weekly slot works — consistency
of cadence matters more than which day. Note the day chosen so the next
pass starts from a known baseline rather than an arbitrary one.

## 6. Output

One short prose block per stream (classes / research / applications):
what changed since last pass, what's now overdue or at risk against the
application timeline, and the top items handed to `priority-triage` for
this week.
