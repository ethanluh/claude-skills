# Positioning & GTM for side projects

Positioning isn't a tagline-writing exercise — it's deciding what the thing
is actually for, before any copy gets written. Run this five-step pass
(even in miniature: a sentence or two per step is enough for a student
project) before drafting a README tagline, landing page, or launch post.

## The five steps

1. **Name the competitive alternatives.** What would the target user do if
   this project didn't exist? Include the overlooked default — a
   spreadsheet, a manual process, "nothing" — not just direct competing
   tools. Positioning against "do nothing" is a common blind spot; skipping
   it makes the value proposition vague.

2. **Inventory unique attributes.** List what this project genuinely has
   that the alternatives above lack. Compare honestly against what you
   listed in step 1 — don't assume differentiation that isn't there.

3. **Translate attributes into value.** An attribute only matters if it
   maps to something the target reader already recognizes as valuable.
   "Written in Rust" or "uses a novel algorithm" is not automatically a
   selling point — say what it lets the reader do or avoid instead
   (faster startup, no runtime dependency, fewer crashes). This is the
   step technical founders skip most often.

4. **Define the target segment.** Not "everyone" — the specific group
   whose situation makes the step-3 value obvious to them without
   explanation. Who feels the pain from step 1 alternatives most acutely?

5. **Pick the market frame.** Situate the project in a category that makes
   its value legible at a glance. Sometimes the honest frame isn't the
   obvious one — Dunford's example repositioned a helpdesk tool around
   "human-centered customer service" rather than price, which resonated
   with a segment that saw service as a loyalty driver. Pick the frame
   that makes the value obvious to the step-4 segment, even if it's an
   unexpected category.

## When to lock it in

For early-stage or unvalidated projects, don't lock positioning in before
you have signal. Let early users pull you toward the real segment and
value; only commit to a fixed tagline/frame once a consistent customer
pattern emerges (similar size, tools, or growth stage among the people who
actually respond).

## Output

A one-paragraph answer covering all five steps, done before the README
tagline or launch-post title — not after. If a step comes back empty
(especially step 3, translated value), that's the signal to keep
iterating on positioning rather than start writing copy.
