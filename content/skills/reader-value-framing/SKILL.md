# Reader-Value Framing

Two modes, one root idea: writing works only if it changes how a specific
reader thinks. That never happens by the writer offloading everything they
know; it happens by meeting the reader where their attention already is.

## Mode 1: Problem/Response framing (structural)

Source: Larry McEnerney, "The Craft of Writing Effectively."

- **Value lives in the reader, not the content.** A true, well-supported
  point can still be worthless if this specific audience doesn't already
  care about the question it answers. Before drafting, name the community of
  readers and what they already treat as valuable or unresolved; don't
  infer this while writing.
- **Diagnose the opening pattern.** Academic default: Background, then
  Definition, then Thesis. This establishes continuity and reads as static;
  readers disengage because nothing is unsettled yet. Replace it with
  Problem, then Response: open on instability, not settled background.
- **Check for an instability marker in paragraph one.** Words like
  "however," "although," "surprisingly," "inconsistent," "yet" signal to a
  scanning reader that value is about to be created. If the first paragraph
  has none, it's still in Background mode; rewrite the opening before
  touching anything downstream.
- **Don't confuse this with simplifying.** This mode is about the shape of
  the document (what's unresolved and pulls the reader forward), not about
  vocabulary level. A highly technical paper and a plain-English memo both
  need a problem/response opening; only Mode 2 addresses jargon and
  reading level.
- **Applies beyond intros.** Section transitions and cover-letter/proposal
  openings benefit from the same check: does this paragraph continue
  something settled, or does it reopen a tension the reader hasn't
  resolved?

## Mode 2: General-audience adaptation (sentence/document level)

Source: Google's "Technical Writing One."

Use this mode when the reader is a smart non-expert and the "curse of
knowledge" is the risk: once you understand something, it's hard to
remember what it's like not to.

- **State the audience and prior-knowledge split explicitly, in writing,
  before drafting.** Who is this for, and what do they already know versus
  need to learn? Don't intuit this mid-draft; write it down as a discrete
  first step.
- **Front-load key points.** State the main takeaway at the start of the
  document; define scope and intended audience before the technical content
  begins. This is the same front-loading principle as Mode 1's
  problem/response opening, applied at the document level.
- **Run a mechanical active-voice pass.** Convert passive constructions
  where active gives clearer subject/responsibility and a shorter sentence.
  Not a blanket "always active" rule; apply it where it demonstrably
  clarifies.
- **Run a mechanical ambiguous-pronoun pass.** Hunt "it," "this," "that,"
  "these" and confirm each has one unambiguous referent within the same or
  prior sentence. If a pronoun could point to two things, name the noun
  instead.
- **Enforce terminology discipline.** Define each term or abbreviation once,
  then use it consistently; never swap in a synonym for variety.
- **Paragraph-level checks:** strong lead sentence per paragraph, one topic
  per paragraph, and a deliberate (not default) choice between bulleted and
  numbered lists.
- **Know the ceiling.** This mode is a mechanical foundation, not mastery;
  treat it as a pass to run every time, not a one-time fix.

## Applying both modes together

For a technical write-up aimed at a general reader (blog post, portfolio
case study, grad-school SOP): run Mode 1 first to fix the shape (problem the
reader already cares about, instability marker up front), then run Mode 2 as
a sentence-level pass over the resulting draft (audience statement, active
voice, pronoun check, front-loaded key points). Doing Mode 2 first without
Mode 1 produces clear sentences arranged in a still-static, background-first
shape.
